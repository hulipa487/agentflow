AgentFlow

A single-binary, self-hosted LLM agent runtime built in Go and Luau. Configure the ordinary; program the exceptional.

What it is

AgentFlow runs LLM-powered agents that can remember, use tools, execute shell commands, schedule background work, talk to other agents, and serve users through webhooks and Telegram. Every agent is defined declaratively in YAML; all behavior beyond the defaults comes from hot-reloadable Lua plugins that hook into versioned interfaces exposed by the core.

Design principles

  • Core provides capabilities; plugins provide behavior; YAML provides wiring.
  • One Luau state per session — actor model, message-passing only.
  • Failure defaults to truthful — unavailable tools return structured errors, never fabricated results.
  • Builtins are plugins — shipped in the binary, shadowable by name, same contract as user plugins.
  • The capability boundary is a message protocol — not a language API.

Current status: Phases 0–4 complete. The core runtime (actors, memory, tools, shell, multi-agent, scheduler, budget, safety, metrics) is implemented and tested. Every storage backend is a real provider — SQLite, Redis, MongoDB, and PostgreSQL for KV/document storage, and pgvector for vector recall (SQLite vector queries return an explicit unsupported error, never silent empties). LLM providers cover all three compatible API shapes: Anthropic Messages, OpenAI Chat Completions, and OpenAI Responses, each targeting self-hosted/proxied endpoints via base_url. Channels: webhook, and Telegram in both polling and webhook modes. Embeddings (llm.embed, OpenAI-compatible) and cross-encoder reranking (llm.rerank) close the semantic-memory loop: pgvector stores vectors on write and builtin:semantic recall pipelines embed -> vector k-NN -> rerank.

Install Guide

Prerequisites

  • Go 1.25+ — the runtime is built with Go modules.
  • GNU make — drives the Luau static library + Go binary build.
  • A C/C++ toolchain for the Luau cgo bridge. The Makefile auto-selects by host OS:
    • Windows: zig (hermetic; no system gcc required).
    • Linux: system gcc (cc/c++/ar), usually from build-essential.
    • macOS: Xcode / Apple Command Line Tools (clang/clang++/ar).

Luau itself is vendored under third_party/luau/ (version 0.731, MIT), so a clean clone builds without fetching anything else.

Windows

  1. Install Go and ensure go version reports 1.25+.
  2. Install Git for Windows (includes Git Bash).
  3. Install zig and add it to your PATH.
  4. Install GNU make. The easiest route on Windows is choco install make via Chocolatey, or use the make bundled with Git Bash/MSYS2.
  5. Clone and build from Git Bash (not cmd.exe): 
    git clone https://github.com/\<you\>/agentflow.git
make            # compiles vendored Luau -> internal/vm/lib/libluau.a, then agentflow
make test       # run the Go test suite
make vet        # run go vet with cgo enabled
Important: The Makefile uses Unix shell recipes (rm -rf, mkdir -p, ./$(BIN)). If you run make from cmd.exe you will see errors such as "The system cannot find the file specified." Run it from Git Bash, or force a bash shell with make SHELL="C:\Program Files\Git\bin\bash.exe".

Linux

  1. Install Go and a C++ toolchain: 
    # Debian/Ubuntu
sudo apt update
sudo apt install -y golang-go build-essential

# Fedora
sudo dnf install -y golang gcc gcc-c++ make
  2. Clone and build: 
    git clone https://github.com/\<you\>/agentflow.git
make && make test

macOS

  1. Install Go from go.dev or Homebrew: brew install go.
  2. Install Xcode Command Line Tools: xcode-select --install.
  3. Clone and build: 
    git clone https://github.com/\<you\>/agentflow.git
make && make test

Verify the install

Run the no-model echo example and hit it with curl:

./agentflow -config examples/agentflow.minimal.yaml
# in another terminal:
curl -X POST localhost:8080/webhook -d '{"from":"alice","text":"hello"}'

You should see echo: hello in the response. Also check the admin endpoints:

curl http://127.0.0.1:9090/healthz
curl http://127.0.0.1:9090/readyz

Architecture

A request flows vertically through five layers: channels carry bytes in, the core authorities (safety, router, supervisor) decide where they go, per-session actors run a Luau loop, the loop calls capability-backed ops through the async bridge, and drivers reach external systems. Each layer is independently substitutable.

┌─ Channels (bytes in / replies out) ──────────────────────────────────────────┐
│  webhook          telegram:polling          telegram:webhook                  │
│  (POST handler)   (getUpdates loop)         (POST /telegram/<name>)          │
└───────────┬───────────────────┬──────────────────────┬───────────────────────┘
            │                   │                      │
            ▼                   ▼                      ▼
┌─ Gateway & Router ──────────────────────────────────────────────────────────┐
│  gateway.ingress  ──►  safety.ingress (core-owned)  ──►  gateway.route   │
│  (per_chat)            signal gate / affect guard       (session authority)   │
└───────────┬──────────────────────────────────────────────────────────────────┘
            │ inbound Message{to, from, provenance}   provenance core-stamped
            ▼
┌─ Supervisor (address authority + ACL + lifecycle) ─────────────────────────┐
│  parse addr ──► enforce can_contact ──► deliver to session mailbox          │
│  spawn / request / reply  ·  ephemeral children  ·  cleanup on death         │
└───────────┬──────────────────────────────────────────────────────────────────┘
            │ one mailbox per session
            ▼
┌─ Actor (1 goroutine + 1 Luau state per session) ───────────────────────────┐
│  inbox ──► loop() ──► llm.chat / tools.run / shell.exec / agent.send / …     │
└───────────┬──────────────────────────────────────────────────────────────────┘
            │ __af_op(json) yield ── Go worker pool resumes with result
            ▼
┌─ Capabilities & Drivers ────────────────────────────────────────────────────┐
│  llm:    anthropic · openai · openai-responses   (base_url → compatible host)│
│  memory: sqlite · redis · mongodb · postgres     pgvector (vector recall)    │
│  shell:  docker · ssh                             tools: builtins + mcp      │
└──────────────────────────────────────────────────────────────────────────────┘
            │ outbound reply
            ▼
┌─ Egress ───────────────────────────────────────────────────────────────────┐
│  safety.egress (core-owned)  ──►  gateway.egress  ──►  channel Deliver  │
└────────────────────────────────────────────────────────────────────────────┘

Functional flow — one user turn

user ─► [channel]
          │ normalize → session.Message{from, text}
          ▼
       gateway.ingress ─► safety.ingress ─► gateway.route
          │                                  (per_chat → session id)
          ▼                                     │
       supervisor.deliver ◄─────────────────────┘
          │ enforce can_contact, stamp provenance, enqueue mailbox
          ▼
       actor mailbox ◄──── scheduler.every / after / cron ── (timer messages)
          ▼
       loop() resumes
          │  ├─ memory.recall(history)        ── async bridge ──► store backend
          │  ├─ llm.chat(messages)            ── async bridge ──► llm driver
          │  ├─ loop.on_tool_call → tools.run ── async bridge ──► tool / mcp / shell
          │  └─ memory.write(record)          ── async bridge ──► store backend
          ▼
       session.send(reply)
          ▼
       safety.egress ─► gateway.egress ─► channel.Deliver ─► user

Multi-agent orchestration

Static agents (each with its own model + instructions) collaborate via agent.send/agent.request under can_contact ACLs; ephemeral children are spawned from profiles.agent templates with capability attenuation. A reference orchestrator (main + expert + project manager + workers) is a common pattern built on these primitives — it lives outside this runtime, in a separate product repo:

chit-chat:      user ──telegram/webhook──► main ──llm──► user

expert consult: user ──► main ──[directive: consult]──► expert_code (agent.request)
                                    ◄── opinion ── (agent.reply)
                          main ──llm (fold opinion)──► user

project launch: user ──► main ──[directive: start_project]──► agent.spawn("project_manager")
                          main ─► PM: brief{goal, channel, reply_to, chat_key}
                          PM ── decompose → store tasks ── spawn N workers
                          PM ──► worker: task      worker ──► PM: report
                          PM ──► main: {kind: milestone|decision|notify, ...}
                          main ──session.push(channel, reply_to, text)──► user  (idle-time push)
                          PM ── shutdown workers ── session.exit()

session.push (cap channel.push) is proactive egress — a background agent reaches the user without an active inbound message. session.exit terminates a spawned session cleanly (the parent receives agent.died). The orchestrator wiring and role prompts ship with the reference product repo, not this runtime.

Layer responsibilities

LayerOwnsDescription
channelsTransportNormalize raw platform bytes into the shared session.Message and format replies back out.
gateway / routerRoutingRun gateway.ingress, the core-owned safety.ingress gate, and gateway.route to resolve a session address.
supervisorAuthorityAddress parsing, can_contact ACL, provenance stamping, mailbox delivery, spawn/request/reply, lifecycle cleanup.
actorExecutionOne goroutine + one Luau state per session. Drives the loop, parks on __af_op, resumes on results.
capabilitiesOpsLua-facing tables (llm, memory, tools, shell, agent, scheduler) each wrapping the single async-bridge primitive.
driversI/OReach real systems: LLM providers, storage/vector backends, shell providers, MCP servers.
safetyGuardCore-owned, runs on ingress and egress regardless of the loop handler. Cannot be uninstalled from Lua.

Quick Start

Build

The Makefile compiles the vendored Luau VM bridge via cgo (zig as the hermetic C compiler), then the binary:

make        # luau static lib -> agentflow binary
make test   # go test with the cgo/zig toolchain

Run

The fastest path needs no model — the echo example replies with a file-based loop:

./agentflow -config examples/agentflow.minimal.yaml
curl -X POST localhost:8080/webhook -d '{"from":"alice","text":"hello"}'

For an LLM-backed bot, point a real model at it (next block) and use examples/agentflow.compatible.yaml as a template.

Connect a real model

AgentFlow targets Anthropic/OpenAI-compatible proxies and gateways — not the official APIs. Set base_url to your endpoint:

models:
  default:
    provider: openai          # API shape: anthropic | openai | openai-responses
    model: gpt-4o
    base_url: http://127.0.0.1:11434/v1   # Ollama / vLLM / LiteLLM / OpenRouter
    api_key: ${OPENAI_API_KEY}

provider selects the request/response format. base_url selects the host. api_key may be empty for keyless local endpoints (Ollama).

Configuration Guide

AgentFlow is configured through a single YAML file (agentflow.yaml). Every value is validated at boot — an unknown key is a boot error with file and line, never a runtime surprise. Environment interpolation (${VAR} and ${VAR:-default}) is supported anywhere a string is accepted.

File skeleton

version: "1"

runtime:    { ... }   # core tuning: VM limits, workers, reload, persistence, admin
models:     { ... }   # named LLM providers
memory:     { ... }   # instance-wide backend instances
profiles:   { ... }   # reusable configs: memory/, safety/, shell/, agent/
gateway:    { ... }   # channels
mcp:        { ... }   # MCP servers
tools:      { ... }   # global tool policy
agents:     { ... }   # the agents themselves
plugins:    { ... }   # plugin dir, capability ceiling

Philosophy

YAML defines topology — what exists and how it's wired. Behavior lives in Lua plugins. Parameters live in YAML. This separation means a working chatbot is a ~12-line YAML with zero code, while every point in the pipeline remains overridable.

Strict parsing: KnownFields(true) means every unknown key is a boot error. There are no "ignored" typos.

Lua Plugin Development

AgentFlow plugins are plain Luau scripts. YAML defines which plugin runs for which agent; the plugin defines the behavior. There are three kinds of plugin:

  • Loop plugin — defines a global loop() function that owns the session coroutine for its lifetime. The canonical pattern is while true do local msg = session.inbox() ... end.
  • Support chunk — loaded into every session state before the loop plugin. Support chunks define globals and helper functions the loop reads. Builtins like builtin:token_budget, builtin:routing_table, builtin:recency, builtin:semantic, builtin:fact_extractor, builtin:exec_policy, and builtin:ttl are support chunks.
  • Shadow — a user plugin placed in plugins/ with the same name as a builtin. It replaces the builtin instance-wide at load time.

The async bridge

The only native primitive exposed to Luau is __af_op(json_request). It yields the coroutine; Go executes the request (inline or on a worker pool); then the coroutine resumes with (json_response, ok). The prelude wraps this raw primitive into the friendly tables documented below. Because every call yields, a busy instance stays cheap — no OS thread is blocked waiting for a model, database, or HTTP response.

-- What the prelude does for you (conceptually):
local function op(req)
  local resp, ok = __af_op(json.encode(req))
  if not ok then error(resp, 0) end
  return json.decode(resp)
end

Blocking ops include send, llm.chat, tools.run, all store.*, all shell.*, http.request, agent.*, and scheduler.*. Fast ops like inbox, log, and agent.info run inline on the actor goroutine.

Message lifecycle

session.inbox() parks the coroutine until the session mailbox receives a message. A message is a table with at least:

{
  id = "msg-...",
  type = "user",           -- "user" | "system" | "timer" | "agent" | ...
  from = "webhook:alice",  -- core-stamped sender
  text = "hello",
  channel = "webhook",
  reply_to = "...",
  ts = 1234567890
}

session.send(text) replies through the active channel (the channel and reply target of the current message). session.push(channel, reply_to, text) sends proactively and requires the channel.push capability. session.push_user(uuid, text) pushes to a user by identity UUID. session.exit() terminates the session cleanly.

Writing a loop plugin

A minimal echo loop looks like this (plugins/examples/echo.lua):

log.info("echo agent online")

function loop()
  while true do
    local msg = session.inbox()
    log.info("message from " .. (msg.from or "?"))
    time.sleep(0.3)
    session.send("echo: " .. (msg.text or ""))
  end
end

A ReAct-style loop that calls an LLM and optionally tools is the builtin:react plugin. You can copy it as a starting point for custom reasoning patterns.

Built-in Lua API reference

All tables below are injected only when the agent's capabilities allow them. Attempting to call a disabled API raises an error.

session — core

session.inbox() -> Message            -- parks until the next mailbox message
session.send(text)                    -- reply to the active inbound message
session.push(channel, reply_to, text) -- proactive egress; cap: channel.push
session.push_user(uuid, text)         -- proactive egress to a user UUID; cap: channel.push
session.exit()                        -- terminate this session

llm — cap: llm.chat

llm.chat(messages, opts?) -> { text, usage, tool_calls }
llm.stream(messages, opts?) -> iterator
llm.embed(texts, opts?) -> { vectors, usage }     -- texts: string or array
llm.rerank(query, documents, opts?) -> { results } -- results: [{ index, score }], 0-based

-- opts: { model = "default", temperature = 0.7, max_tokens = 4096,
--         tools = [...], tool_choice = "auto" | "none" }

Messages are arrays of { role, content, tool_calls?, tool_call_id?, tool_result? }. llm.stream returns a closure; call it directly (local d = next_chunk()), never in a generic for ... in — the iterator protocol cannot yield across the C boundary.

llm.embed works with any OpenAI-compatible /embeddings endpoint (Ollama, vLLM, TEI, OpenRouter); the Anthropic provider has no embeddings API and fails explicitly. llm.rerank requires a provider: rerank model entry speaking POST {base_url}/rerank (TEI, vLLM, Jina, Cohere). llm.embed is token-metered when the agent declares a budget.

agent — caps: agent.send, agent.request, agent.spawn

agent.info() -> { name, session_id, address, model, instructions,
                  history_budget, memory, shell, skills, capabilities, ... }
agent.send(address, payload)
agent.request(address, payload, timeout?) -> Message
agent.reply(request_id, payload)
agent.list() -> [{ session_id, agent, parent_id }]
agent.spawn(profile, spec?) -> { address, session_id, agent }

scheduler — cap: scheduler

scheduler.every(interval) -> timer_id    -- seconds; dies with session
scheduler.after(delay) -> timer_id
scheduler.cron(expr) -> timer_id          -- standard 5-field cron
scheduler.cancel(timer_id)

Timers enqueue a Message{ type = "timer" } into the owning session's mailbox. They never call Lua from a timer goroutine, so the VM stays single-threaded.

memory and store — cap: memory / store.raw

memory.write(record) -> boolean          -- routed by builtin:routing_table
memory.recall(query, opts?) -> {records} -- active recall handler

store.put(table, key, value, opts?)      -- opts: { ttl = seconds, vector = {...} }
store.get(table, key) -> { value, found }
store.query(table, query) -> { records }
store.delete(table, key)

Store queries accept { kind = "all" | "prefix" | "text" | "vector" | "time_range", ... }; vector queries take { kind = "vector", vector = {...}, k = n }. Passing a vector to a store whose backend lacks the vector feature is an explicit error, never a silent drop. Prefer memory.write/memory.recall for agent memory; use store.* only when you need raw table access.

tools — cap: tools

tools.list() -> [ToolSpec]
tools.run(name, args, opts?) -> ToolResult
-- opts: { confirmed = true, confirm_id = "..." }

If a tool declares needs_confirm: true, the first call returns a needs_confirm response. The runtime asks the user, then re-invokes the tool with opts.confirmed = true. Your loop sees only the final result.

shell — cap: shell.exec

shell.spawn(opts) -> { id, provider, state }
shell.exec(id, cmd) -> { stdout, stderr, exit_code, duration_ms }
shell.write(id, path, content)
shell.read(id, path) -> content   -- capability table; also available as builtin:fs.read
shell.destroy(id)

-- spawn opts:
-- { provider = "docker", image = "alpine:3.20", workdir = "/work",
--   network = "none", mem_limit = "512m", cpu_limit = 1.0,
--   env = { KEY = "val" },

--   host = "1.2.3.4:22", user = "root", password = "...", key_file = "/path" }

Writing support chunks

Support chunks are evaluated into the session state before the loop plugin. They can define globals that the loop or other support chunks read. For example, to replace the default recall strategy, shadow builtin:recency with a file in plugins/recency.lua that defines memory_recall_handler(query, opts).

-- plugins/recency.lua (shadow example)
function memory_recall_handler(query, opts)
  local info = agent.info()
  local store_name = (info.memory and info.memory.stores.dialogue) or "dialogue"
  local res = store.query(store_name, { kind = "all" })
  return res.records or {}
end

Error handling

Always wrap external calls in pcall so a sick provider or bad command does not crash-loop the session:

local ok, reply = pcall(llm.chat, messages, { model = info.model })
if not ok then
  log.warn("llm.chat failed: " .. tostring(reply))
  session.send("⚠️ I couldn't reach my model right now.")
  return
end

The bridge returns errors as JSON strings; the prelude unwraps them so stack traces point to your code, not the prelude.

Confirmation and permissions

Tools and shell builtins can declare needs_confirm. The first tools.run returns a result with needs_confirm = true and a confirm_id; the actor asks the user, then re-invokes the tool with opts.confirmed = true and the same confirm_id. Your loop sees only the final result, so in most cases you do not need to handle confirmation manually.

Restrictions and caveats

  • llm.stream returns a closure — call it directly, never in a generic for ... in.
  • The standard library includes base, coroutine, table, string, math, bit32, utf8, and buffer. io, os (except the prelude's os.env), and debug are not available.
  • Raw network access from Lua is only through http.request. There is no socket library.
  • All values crossing the bridge are JSON-encoded. Tables must be serializable; functions and userdata cannot cross.
  • Plugins are hot-reloadable when runtime.reload.watch is true. Edits to a loop file or instructions file restart the session coroutine from scratch on the next turn.

Tool loop

function loop()
  while true do
    local msg = session.inbox()
    if msg.type == "user" and msg.text then
      local info = agent.info()
      local tools = tools.list()
      local ok, reply = pcall(llm.chat,
        { { role = "user", content = msg.text } },
        { model = info.model, tools = tools, tool_choice = "auto" })
      if ok and reply.tool_calls then
        for _, tc in ipairs(reply.tool_calls) do
          local r = tools.run(tc.name, tc.args)
          log.info("tool result: " .. json.encode(r))
        end
        session.send(reply.text or "done")
      elseif ok then
        session.send(reply.text or "")
      else
        session.send("error: " .. tostring(reply))
      end
    end
  end
end

Shell loop

function loop()
  while true do
    local msg = session.inbox()
    if msg.type == "user" and msg.text then
      local h = shell.spawn({ provider = "docker", image = "alpine:3.20" })
      local r = shell.exec(h.id, "echo hello from " .. msg.text)
      shell.destroy(h.id)
      session.send("exit=" .. r.exit_code .. " stdout=" .. r.stdout)
    end
  end
end

Multi-agent request

function loop()
  while true do
    local msg = session.inbox()
    if msg.type == "user" and msg.text then
      local ok, answer = pcall(agent.request, "agent:expert", { question = msg.text }, 30)
      if ok then
        session.send("expert says: " .. (answer.payload and answer.payload.answer or "?"))
      else
        session.send("expert unavailable: " .. tostring(answer))
      end
    end
  end
end

Native Capability API

These are the Lua-facing tables exposed by the prelude. Each wraps the single __af_op yield primitive. The capability a table requires must be in the agent's effective grants.

llm — cap: llm.chat

llm.chat(messages, opts?) -> { text, usage }
llm.stream(messages, opts?) -> iterator    -- yields chunks; call directly, not in for-in
llm.embed(texts, opts?) -> { vectors, usage }      -- OpenAI-compatible /embeddings endpoints
llm.rerank(query, documents, opts?) -> { results }  -- provider: rerank (POST /rerank)

session — core

session.inbox() -> Message                    -- the loop's consumption point
session.send(text_or_message)               -- egress through the active channel
session.push(channel, reply_to, text)        -- proactive egress; cap: channel.push
session.exit()                               -- terminate this session (no restart)

agent — caps: agent.send, agent.request, agent.spawn

agent.info() -> { name, session_id, address, model, instructions, history_budget, memory, shell, ... }
agent.send(addr, payload)                    -- "agent:name" | "session:id"
agent.request(addr, payload, timeout) -> Message   -- error on timeout
agent.reply(request_id, payload)             -- resolve a parked request
agent.spawn(profile, spec) -> { address, session_id, agent }
agent.list() -> [{ session_id, agent, parent_id }]

scheduler — cap: scheduler

scheduler.every(interval, fn) -> Timer       -- dies with session
scheduler.after(delay, fn) -> Timer
scheduler.cron(expr, fn) -> Timer
scheduler.cancel(timer)

Timers enqueue Message{Type:"timer"} to the owning session's mailbox — they never invoke a Luau state from a timer goroutine.

memory — cap: memory

memory.write(record) -> boolean             -- through memory.write chain
memory.recall(query, opts?) -> {Memory}      -- active recall handler
store.put(table, key, value, opts?)          -- low-level
store.get(table, key) -> { value, found }
store.query(table, query) -> { records }
store.delete(table, key)

tools — cap: tools

tools.list() -> [ToolSpec]
tools.run(name, args, opts?) -> ToolResult   -- same permission gate as LLM calls

shell — cap: shell.exec

shell.spawn(opts) -> ShellHandle              -- through shell.provision handler
shell.exec(handle, cmd) -> ExecResult        -- through shell.before_exec filter
shell.write(handle, path, content)
shell.read(handle, path) -> content
shell.destroy(handle)
